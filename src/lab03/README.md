# ЛР-3 — Наследование и иерархия классов

## 1. Цель работы

- Освоить наследование и построение иерархии классов.
- Научиться переиспользовать код через `super()`.
- Реализовать полиморфизм через переопределение методов.
- Интегрировать иерархию с коллекцией из ЛР-2.

## 2. Описание реализованной иерархии

```
BankAccount (base.py)
 ├── CreditAccount  (models.py) — кредитный счёт с лимитом и долгом
 └── DepositAccount (models.py) — вклад с замороженным сроком
```

### `BankAccount` (базовый)

Тот же класс, что и в ЛР-1: номер счёта, владелец, баланс, ставка,
состояние «активен/заблокирован», `deposit`/`withdraw`/`apply_interest`.

Атрибут класса `kind = "Базовый счёт"` нужен для полиморфного
`__str__` — потомки переопределяют его, и базовый `__str__` сам
подхватывает нужное название.

### `CreditAccount` — кредитный счёт

**Новые атрибуты:** `_credit_limit`, `_debt`.
**Новые методы:** `pay_debt(amount)`, свойство `available`.
**Переопределено:**
- `withdraw()` — позволяет снимать деньги, уходя в долг до `credit_limit`;
- `apply_interest()` — проценты идут не на остаток, а на **долг**
  (логика кредита — банк нам начисляет, а не наоборот);
- `__str__()` — добавляет инфу о долге через `super().__str__()`.

### `DepositAccount` — вклад

**Новые атрибуты:** `_term_months`, `_is_matured`.
**Новые методы:** `mature()` — открыть вклад после истечения срока.
**Переопределено:**
- `withdraw()` — пока вклад не созрел, снять нельзя (`RuntimeError`).
  После `mature()` ведёт себя как обычный счёт через `super().withdraw()`;
- `__str__()` — добавляет состояние вклада.

### Интеграция с коллекцией

`AccountBook` (`collection.py`) хранит объекты типа `BankAccount` и его
наследников — сам по себе isinstance-чек этого достаточен. Добавлены
два фильтра по типу: `get_only_credit()` и `get_only_deposit()`.

## 3. Демонстрация работы

В `demo.py` три сценария.

**Сценарий 1.** Кладём в коллекцию счета трёх разных типов
(`BankAccount`, `CreditAccount`, `DepositAccount`). Дёргаем
`apply_interest()` в одном цикле — каждый счёт обрабатывается
по-своему: у обычного и вклада растёт баланс, у кредитного — растёт
долг. Это полиморфизм без `if isinstance(...)` в вызывающем коде.

**Сценарий 2.** Специфические методы потомков. У `CreditAccount`
снимаем больше, чем есть на балансе — недостача уходит в долг.
Гасим часть долга через `pay_debt()`. У `DepositAccount` пробуем
снять — отбивается `RuntimeError`. После `mature()` снятие работает.

**Сценарий 3.** Фильтрация коллекции по типу через `get_only_credit()`
и `get_only_deposit()`. В конце — таблица проверок `isinstance`,
показывающая, что иерархия выстроена корректно.

## 4. Вывод

- Наследование позволило не дублировать общий код (`super()` в конструкторе).
- Полиморфизм через переопределение `withdraw` и `apply_interest`
  избавляет от ветвления `if isinstance(...)` в коде, который работает
  с коллекцией счетов.
- Атрибут класса `kind` показал, как наследование работает не только
  для методов, но и для атрибутов уровня класса.
