# ЛР-4 — Интерфейсы (ABC)

Сделал два контракта поведения — `Printable` и `Comparable` — через
`abc.ABC`. Это типа «договор»: классу прописывают, какие методы он
**обязан** реализовать, а как именно — его дело.

## Что в папке

- `interfaces.py` — два ABC: `Printable.to_string()` и `Comparable.compare_to()`
- `models.py` — иерархия из ЛР-3, реализующая оба интерфейса
- `collection.py` — коллекция с фильтрами и сортировкой через интерфейс
- `demo.py`, `README.md`

```
cd src/lab04
python3 demo.py
```

## Интерфейсы

**`Printable`** — обязательный метод `to_string() -> str`. Для
красивого вывода объекта.

**`Comparable`** — обязательный метод `compare_to(other) -> int`,
возвращает `-1 / 0 / +1`. Для сортировки и поиска максимума.

## Кто что реализует

`BankAccount` подписался **сразу на оба** интерфейса:
`class BankAccount(Printable, Comparable)`. Это множественная
реализация интерфейсов — нормальная история.

`CreditAccount` и `DepositAccount` наследуются от `BankAccount` —
оба контракта они получают автоматом, плюс переопределяют
`to_string()` через `super()`, чтоб дописать своё (про долг или
про состояние вклада). Сравнение `compare_to` оставили базовое — по
балансу.

## Коллекция и универсальные функции

В `collection.py`:

- `get_printable()` / `get_comparable()` — фильтр по интерфейсу
- `sort_via_comparable()` — сортирует через `compare_to` (объекты
  сами знают, кто из них больше; ключ извне не нужен)
- `print_all(items)` — печатает любую коллекцию `Printable`-ов
- `find_max(items)` — находит максимум через `Comparable`

Главная фишка: `find_max` и `print_all` ничего не знают про
`BankAccount`. Появится новый класс с теми же методами — функции
с ним сразу заработают.

## Что в `demo.py`

1. Три счёта разных типов через `to_string()` — у каждого свой
   формат. Один интерфейс — три реализации.
2. Универсальные `find_max(accounts)` и `isinstance`-проверки. Видно,
   что класс реализует оба контракта одновременно.
3. Фильтр по интерфейсу + `sort_via_comparable()` — отсортировано
   без указания ключа сортировки.
4. Класс-наследник `Printable`, который забыл реализовать
   `to_string()`, тупо не создаётся — Python кидает `TypeError`
   на `__init__`. Это и есть смысл контракта: забыть метод нельзя,
   ругнётся сразу.

## Что вынес

ABC — это форсированный контракт: Python не даст создать объект,
если обязательный метод не реализован. И главный плюс — функции,
работающие через интерфейс, пишутся **один раз** и работают со всем,
что подписалось под этот контракт.
