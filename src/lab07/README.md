# лр-7 — консольное приложение
## что в папке

```
main.py       ← вход. автозагрузка → cli → автосохранение
cli.py        ← ввод/вывод. меню, таблицы, y/n
app.py        ← бизнес-логика. AccountService поверх TypedCollection
models.py     ← счета. копия из лр-6, не трогаем
container.py  ← TypedCollection[T]. тоже из лр-6
exceptions.py ← свои ошибки предметки
storage.py    ← json save/load
data.json     ← появится после первого запуска
```

запуск:

```
cd src/lab07
python3 main.py
```

## три слоя

главное: **cli не знает про устройство счетов**, сервис **не знает про файлы**.
каждый слой смотрит только вниз.

```
main.py     ──┐ (знает всё, сшивает)
              │
cli.py    ───►│  app.py  ───►  models.py + container.py
              │       │
              │       └───►  exceptions.py
              │
              └───►  storage.py  ───►  models.py
```

по импортам:

- `cli.py` тянет только `app` + `exceptions`. **ничего** из `models` /
  `container` / `storage`.
- новые счета — через фабрики сервиса: `service.create_basic / credit / deposit`.
- таблица рисуется через `account_view(acc) -> dict` — cli ходит по
  ключам словаря и не лезет в .debt / .term_months.
- список типов — константа `ACCOUNT_KINDS` в app. меню берёт оттуда,
  фильтр тоже оттуда.

→ завтра меняешь модели, иерархию, хранилище — **cli трогать не надо**.

## свои исключения

`exceptions.py` — четыре штуки, общий предок `AccountError`:

```python
class AccountNotFoundError(AccountError):     # такого счёта нет
class DuplicateAccountError(AccountError):    # уже есть, не дам
class StorageError(AccountError):             # битый json / нет прав
class OperationCancelled(AccountError):       # юзер сказал "не"
```

ловить в cli можно **пачкой** — `except AccountError`. удобно когда
добавишь новое — не забудешь.

`OperationCancelled` — не ошибка. это сигнал «прервись и молчи».
всплывает из глубины ввода до меню одной строчкой → никаких `if`-ов
после каждого `input()`.

## меню

```
1. показать всё
2. добавить счёт            (тип: базовый / кредитный / депозитный)
3. найти по номеру
4. фильтр по типу
5. фильтр по балансу        (диапазон min..max)
6. сортировка               (стратегия + asc/desc)
7. пополнить / снять
8. удалить                  (с y/n)
9. сохранить сейчас
0. выход                    (с автосохранением)
```

стратегии сортировки — словарь `SORT_STRATEGIES` в app: «имя → функция-ключ».
cli рисует пункты из ключей, сервис применяет значение.

→ новая стратегия добавляется **в одном месте**, не в двух.

## ошибки

всё, что вылетает из команды, ловится в **одном** месте — главный цикл
`cli.run`. дальше разбираем по типам:

- `ValueError` → ошибка ввода (валидация модели или парс числа)
- `RuntimeError` → счёт заблокирован и т.п.
- остальное → пусть всплывает, это уже баг

программа из-за плохого ввода **не падает**. пишет ошибку → возвращает в меню.

## json и перезапуск

`storage.py` гоняет список счетов в json.

дискриминатор типа — поле `_type` (`"bank" / "credit" / "deposit"`).
по нему на загрузке решаем, какой класс дёргать:

```json
[
  {"_type": "bank",    "account_number": "...", "balance": 2000.0, "interest_rate": 5.0, "is_active": true},
  {"_type": "credit",  ..., "credit_limit": 10000.0, "debt": 2000.0},
  {"_type": "deposit", ..., "term_months": 12, "is_matured": false}
]
```

состояние (`is_active`, `is_matured`) тоже летит в json — чтоб
заблокированный счёт не **оживал** между запусками.

`data.json` лежит **рядом с main.py**, не в cwd. поэтому запускать
можно хоть из `lab07`, хоть из корня — файл будет тот же.

если json битый на старте — **не стартуем**, говорим ошибку, выходим
с кодом 1. иначе можем затереть пустой коллекцией то, что юзер опечатал
руками. лучше пусть разберётся.

## что получаем в итоге

- **слои = импорты**. протёк один импорт `storage` в `cli` — абстракция
  пробита. остальное декорация.
- **свои исключения** > возврат `None` или магических кодов. по имени
  класса видно что произошло, в `except` ловишь именно нужное.
- **дискриминатор `_type`** — самый дешёвый способ сериализовать
  наследников. без него на загрузке непонятно, какой `__init__` звать.
- **тонкий cli** окупается: бизнес-логику тестишь без меню — дёргаешь
  `AccountService` напрямую и всё.
