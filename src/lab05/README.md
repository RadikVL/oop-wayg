# ЛР-5 — Стратегии и функции высшего порядка

Функция в Python — это тоже значение. Её можно передать как аргумент,
вернуть из другой функции, положить в переменную. На этом и держится
вся лаба.

## Что в папке

- `model.py` — иерархия счетов (из ЛР-3, чтоб лаба запускалась сама)
- `strategies.py` — все функции-стратегии в одном месте
- `collection.py` — `AccountBook` со `sort_by`/`filter_by`/`apply`/`map`
- `demo.py`, `README.md`

```
cd src/lab05
python3 demo.py
```

## Что в `strategies.py`

**Функции-ключи** для `sorted(book, key=...)`: `by_balance`, `by_holder`,
`by_rate`, `by_kind_then_balance` (двухуровневая, через кортеж).

**Предикаты** для фильтров: `is_active`, `is_blocked`, `is_credit`,
`is_deposit`.

**Фабрики функций** (тут включается замыкание — внутренняя функция
помнит параметр снаружи): `make_richer_than(threshold)`,
`make_holder_filter(name)`, `make_rate_in_range(lo, hi)`. Удобно, когда
не хочется плодить `is_richer_than_100`, `is_richer_than_1000` и т.д.

**Преобразователи** для `map`: `to_summary`, `to_balance`, `to_holder`.

**Callable-классы** — функция со состоянием:
- `DiscountStrategy(percent)` — режет баланс на процент;
- `InterestStrategy(bonus_percent)` — начисляет проценты с бонусом.

У них определён `__call__`, поэтому экземпляр вызывается как функция:
`cut = DiscountStrategy(0.1); cut(account)`.

## Коллекция

`AccountBook` теперь умеет:
- `sort_by(key_func)` — сортирует через переданный ключ (in-place,
  возвращает `self`)
- `filter_by(predicate)` — возвращает **новую** коллекцию (исходник
  не трогает)
- `apply(func)` — гонит функцию по всем элементам (in-place, возвращает
  `self`)
- `map(transform)` — возвращает список результатов (тип может быть
  любым)

Все методы возвращают коллекцию или `self` — отсюда цепочки:

```python
book.filter_by(is_active).sort_by(by_balance).apply(InterestStrategy(2))
```

## Что в `demo.py`

1. **Три стратегии сортировки + два фильтра.** `sorted` и `filter`
   принимают функции как аргументы. Двухуровневая сортировка
   `by_kind_then_balance` — через кортеж.
2. **`map`, фабрика функций, методы коллекции.** `make_richer_than(1000)`
   возвращает новый предикат, скармливаем его в `filter_by`. В конце —
   проверка, что лямбда и именованная функция дают одинаковый порядок.
3. **Цепочка операций + замена стратегии.** Один и тот же код
   `filter_by → sort_by → apply`, но в `apply` подсовываем разные
   стратегии — `InterestStrategy(2)` и `DiscountStrategy(0.1)` — и
   получаем разное поведение. Код коллекции при этом не меняется.
   В конце — `DiscountStrategy` вызывается напрямую как функция.

## Что вынес

Когда правила вынесены наружу как функции — коллекция становится
универсальной. Фабрики функций удобны, если правило зависит от
параметра. Callable-класс — это просто функция, у которой есть
состояние и `__repr__`. Цепочки превращают код в декларативный
стиль — пишешь *что* должно получиться, а не *как*.
