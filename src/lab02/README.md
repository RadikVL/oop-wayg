## Что реализовано

### Базовая часть (на 3)

- Хранение объектов `BankAccount` в списке `_items`.
- `add(account)` — добавить счёт. Проверка: только `BankAccount`,
  не дубликат (по номеру счёта).
- `remove(account)` — удалить счёт по объекту.
- `get_all()` — вернуть копию списка (чтобы снаружи не портили внутреннее состояние).

### Расширения (на 4)

- `find_by_number(account_number)` — поиск по номеру счёта.
- `find_by_holder(holder_name)` — поиск всех счетов одного владельца.
- `__len__()` — `len(book)`.
- `__iter__()` — `for acc in book: ...`.
- Ограничение: нельзя добавить счёт с номером, который уже в коллекции.

### На 5

- `__getitem__()` — индексация и срезы (`book[0]`, `book[1:3]`).
- `remove_at(index)` — удаление по индексу.
- Сортировки: `sort_by_balance`, `sort_by_holder`, `sort_by_rate`.
- Фильтры, возвращающие **новую коллекцию** (а не правящие in-place):
  `get_active`, `get_blocked`, `get_richer_than(threshold)`.

Бонусом — `__contains__`, `__hash__` (чтобы счета можно было класть в `set`),
аккуратные `__str__`/`__repr__`.

## Сценарии в `demo.py`

**Сценарий 1.** Добавляем три счёта, печатаем коллекцию, удаляем один,
проверяем, что в коллекцию нельзя положить не-`BankAccount` (`TypeError`).

**Сценарий 2.** Добавляем ещё пару счетов одному и тому же владельцу.
Показываем `len()`, `find_by_number` и `find_by_holder`, итерацию `for`,
а также то, что добавить дубликат по номеру нельзя (`ValueError`).

**Сценарий 3.** Индексация (`book[0]`, `book[-1]`, срез `book[1:3]`),
сортировки (по балансу, по владельцу), фильтры (активные, заблокированные,
богатые) — фильтр возвращает новый `AccountBook`, исходный не меняется.
В конце — `remove_at(0)`.
